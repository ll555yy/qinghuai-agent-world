# 人物关系图谱可视化方案

> 状态：全屏公开互动图与人物档案已实现，后续能力按公开数据契约分期扩展
>
> 更新时间：2026-08-25
> 适用范围：Qinghuai Agent World 玩家端 React 前端

## 1. 方案结论

人物关系图谱定位为“玩家认知图”，不是后台全知调试器。它只把玩家亲历的共同聊天转成可视关系，不读取或推断 NPC 的私有 Goal、Memory、信任值、好感度、紧张度、秘密或初始关系 YAML。

第一阶段采用 `react-force-graph-2d`：

- 与 React 19 直接集成，使用 Canvas 力导向布局。
- 适合当前 6 个角色以及后续几十个公开节点的规模。
- 提供拖动、缩放、悬浮提示、节点点击和活动边粒子效果。
- MIT 许可证；组件按需加载，不增加首屏和世界业务壳的同步体积。

当前数据链路：

```text
FastAPI 公开 RunSnapshot
          │
          ▼
Zustand snapshot.conversations + conversationExperiences + actors
          │
          ▼
buildRelationshipGraph（纯函数、隐私边界）
          │
          ▼
RelationshipGraphPanel（全屏 Canvas 渲染与交互）
          │
          ├── 点击人物 → 图谱内人物档案浮层
          ├── 人设 / 当前状态 / 公开关系 / 中立互动摘要
          └── 平移 / 缩放 / 活动聊天高亮
```

## 2. 产品目标与非目标

### 2.1 目标

- 让玩家快速理解“谁和谁已经发生过互动”。
- 让多人聊天形成的关系变化可见，而不要求玩家翻阅全部聊天记录。
- 在世界持续推进时实时更新，并与现有公开人物卡形成导航闭环。
- 保持图谱可解释：每一条边都能由公开会话记录验证。

### 2.2 非目标

- 不展示 NPC 私有关系矩阵或模型推理。
- 不把“共同聊天”解释成信任、亲密、支持或敌对。
- 不根据同场出现、站位接近或相邻消息伪造因果关系。
- 第一阶段不提供图编辑、关系人工修改、Neo4j 管理或后台分析功能。

## 3. 数据语义

### 3.1 节点

第一阶段每个 `PublicActor` 对应一个人物节点。

| 字段 | 来源 | 用途 |
|---|---|---|
| `id` | `actorId` | 稳定节点标识 |
| `label` | `name`，玩家显示“你” | 画布标签 |
| `role` | 公开 `role` | 悬浮提示 |
| `kind` | `player` / `npc` | 颜色和点击行为 |
| `nodeValue` | 玩家类型和公开会话度数 | 节点视觉尺寸 |
| `fx/fy` | 确定性环形布局 | 保持人物在快照更新后位置稳定 |

节点尺寸只表示公开互动量，不表示人物重要性或隐藏影响力。

### 3.2 边

每个公开会话的历史参与者 `participantHistory` 两两组合成无向边；当前参与者
`participants` 只用于判断连线是否仍然活跃。这样人物离开会话后历史关系不会消失。
同一人物对参加多次会话时聚合为一条边：

```text
conversationCount = 两人共同参加的公开会话数
active            = 是否至少有一场共同会话仍为 open
label             = “N 次共同聊天” + 活动状态
```

三人会话 `[A, B, C]` 生成 `A-B`、`A-C`、`B-C` 三条关系；重复参与者先去重，避免重复计数。

### 3.3 公开互动经历

玩家亲历的会话片段结束时，后端复用既有 `SegmentSummary` 中立摘要生成
`PublicConversationExperience`，并发布 `conversation_experience_recorded` 实时事件。
摘要只包含该片段公开原话能够支持的事实、承诺和待讨论问题，携带参与者、时间及
证据消息 ID。NPC 的 `ExitConsolidation` 私有记忆、Goal 和关系变化不进入该投影。

初始快照会从已持久化的片段摘要重建经历，因此旧存档不需要新增数据库表；实时事件
则保证玩家离开聊天后无需刷新即可在人物档案看到这段经历。

### 3.4 隐私边界

禁止将下列数据加入玩家图谱：

- `INITIAL_RELATIONSHIPS.yaml` 中的 trust、affinity、tension、familiarity。
- NPC Goal、Memory、persona、coreSecrets 和未公开立场草稿。
- 只存在于数据库私有投影或 Agent 上下文中的 actor/topic 关联。

如果未来需要“已发现的关系类型”，必须由后端新增显式公开投影，并携带发现依据；前端不能自行读取私有源数据。

## 4. 界面与交互

### 4.1 入口与全屏布局

- 世界顶栏提供“关系图谱”按钮，计数显示当前公开会话数。
- 图谱覆盖完整地图区域，不参与世界主界面的右侧栏宽度计算。
- 顶部工具栏提供“全部关系 / 与我有关”、重新居中和关闭入口。
- 人物档案是叠加在图谱上的浮动卡片；关闭档案不会关闭图谱。
- 窄屏中档案卡移动到底部并限制高度，Canvas 仍保持全区域尺寸。
- 图例区分玩家、NPC 和正在进行的聊天。

### 4.2 画布行为

- 画布平移与滚轮缩放：用于查看密集区域，不写入服务器。
- 悬浮节点：显示人物姓名与公开身份。
- 点击任意人物：在图谱内打开档案，展示公开背景、印象、当前状态、共同聊天关系、参与过的会话及明确提及该人物的世界事件。
- 活动边：使用灯火橙和移动粒子；历史边使用低饱和槐叶绿。
- 连线中点显示“共同聊天 · N”或“正在聊天”，悬浮时显示完整公开语义。
- 力导向布局停止后执行带安全边距的 `zoomToFit`，保证圆形人物、姓名标签和页脚互不遮挡。
- 每张 spritesheet 记录首帧非透明像素边界；关系图只对人物主体裁切并居中，不使用整格透明留白计算中心。

### 4.3 空状态与可访问性

- 没有共同会话时仍展示全部公开人物，并解释连线的产生条件。
- 画布容器提供人物数和关系数的 ARIA 描述。
- Canvas 之外提供等价的键盘人物入口，可以打开同一档案浮层。
- 关闭按钮有明确的“关闭关系图谱”标签。
- `prefers-reduced-motion` 会停用活动粒子并缩短布局动画。

## 5. 前端架构

### 5.1 模块职责

| 模块 | 职责 |
|---|---|
| `graph/relationshipGraph.ts` | 用完整参与历史将公开快照转换成图数据；不包含渲染和全局状态 |
| `ui/panels/RelationshipGraphPanel.tsx` | 全屏 Canvas 生命周期、尺寸监听、人物档案、样式与交互 |
| `state/uiStore.ts` | 打开和关闭关系图谱面板 |
| `ui/WorldScreen.tsx` | 顶栏入口、全屏覆盖层及延迟加载边界 |
| `game/pixelActorAssets.ts` | 图谱头像可见像素裁切与人物素材清单 |

### 5.2 更新策略

- `snapshot.actors` 或 `snapshot.conversations` 更新时重新执行纯函数转换。
- `conversation_experience_recorded` 到达时增量加入人物档案的公开经历列表。
- React `useMemo` 保证无关面板状态变化不重复构图。
- 图组件允许布局引擎给节点附加 `x/y/vx/vy`；这些坐标不回写 Zustand。
- 当前数据量无需 Web Worker；公开节点超过 300 或边超过 1000 时重新评估布局线程。

### 5.3 代码分块与预算

图谱面板和 Phaser 世界场景都通过 `React.lazy` 延迟加载。Phaser 被固定为独立的 `phaser-runtime` 缓存块：

| 分块 | 预算 | 原因 |
|---|---:|---|
| 普通应用分块 | 500 kB 以内（压缩前） | 保持路由和面板轻量 |
| `phaser-runtime` | 1.2 MB 以内（压缩前） | 已知的第三方游戏引擎运行时 |
| 关系图谱分块 | 250 kB 以内（压缩前） | Canvas 图引擎和面板逻辑 |

构建配置只为已隔离的 Phaser 引擎设置 1.2 MB 上限；业务代码必须通过分块结果单独检查，不能继续堆入引擎块。

## 6. 测试与验收

### 6.1 自动化测试

- 两人多次会话应聚合为一条边并正确累计次数。
- 任一共同会话为 `open` 时，边应为活动状态。
- 人物离开仍在继续的会话后，历史边保留但不再误标为活动关系。
- 三人会话应生成三条不重复的两两边。
- 玩家亲历片段结束后应生成一条中立公开经历，且不能读取 NPC 私有总结。
- 无会话时应保留全部公开人物、边数组为空。
- TypeScript、ESLint、Vitest 和 Vite production build 必须通过。
- `pnpm build`（包含 `check:bundle-size`）必须检查 `dist/assets` 的分块预算；关键分块缺失或超预算时构建失败。

### 6.2 浏览器验收

- 1280×720 下图谱占满地图区域且不压缩为侧栏，人物圆形头像与标签完整可见。
- 点击人物节点能在图谱内打开对应公开资料、关系与经历。
- 六个人物主体均按非透明像素边界在圆圈中居中。
- 新会话到达后无需刷新即可出现或更新边。
- 关闭和重新打开图谱不残留 Canvas、ResizeObserver 或动画循环。
- 控制台无错误；断线状态不阻塞查看已有图谱。

## 7. 分期计划

### 阶段 A：公开互动图（已完成）

- 人物节点、共同会话边、次数聚合和活动边。
- 顶栏入口、全屏地图布局、空状态、缩放和平移。
- 纯函数单元测试、生产构建和浏览器视觉验收。

### 阶段 B：人物档案与关系过滤（已完成）

- “全部关系 / 与我有关”过滤器。
- 图谱内人物档案、人设、公开印象、状态、关系列表和互动经历。
- 连线关系标签、确定性环形布局与人物主体居中裁切。

### 阶段 C：时间维度

- 按 Day 筛选或回放公开互动网络。
- 点击边展示组成该关系的公开会话列表，而不是推断关系含义。
- 为减少运动偏移，保存仅属于当前设备的节点布局偏好。

### 阶段 D：后端公开发现契约

仅在产品确认需要时新增：

- `PublicRelationshipDiscovery`：关系标签、发现时间、公开证据 ID。
- `PublicTopic` 节点及 Actor—Topic 已公开关联。
- 世界事件节点与明确公开的参与者边。

阶段 C 必须先完成后端白名单、Owner-safe 回归测试和隐私审查，之后前端才能消费。

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 玩家把共同聊天误解为好感 | 文案统一使用“共同聊天/公开互动”，不使用亲密度 |
| Canvas 对读屏不友好 | 保留 ARIA 摘要；阶段 B 增加等价的关系列表视图 |
| 高频快照导致布局抖动 | 聚合结果稳定化，后续按节点/边增量更新 |
| 第三方依赖增加包体积 | 独立延迟分块并设置 250 kB 图谱预算 |
| 私有关系意外进入前端 | 转换函数只接受 `RunSnapshot` 公开契约并设置回归测试 |

## 9. 完成定义

第一阶段在满足以下条件时视为完成：

- 玩家能从世界顶栏打开图谱，并看懂节点与连线代表的公开事实。
- 图谱使用完整地图区域；点击人物可在原图谱中查看人设、关系和经历。
- 图谱随公开会话快照更新，聚合逻辑有自动化测试。
- 不存在读取初始私有关系、Goal、Memory 或秘密的前端路径。
- 图谱与 Phaser 均为独立延迟分块，生产构建无体积警告。
- 1280×720 浏览器验收、人物主体居中和档案浮层交互通过。
