```text
继续开发 C:\Users\yangruiqi\Desktop\chat 中的“青槐老巷聊天世界”。

目标：在现有 FastAPI 内存后端和火山方舟 TextModel 适配器之上，完成一个无需数据库和前端即可通过 API、WebSocket 与自动测试运行的“七天 NPC 聊天世界后端可玩闭环”。

开始前完整阅读并遵守：
- project/PROJECT_DESIGN.md
- project/PROJECT_RULES.md
- project/SYSTEM_DESIGN.md
- project/BACKEND_PHASE1_ACCEPTANCE.md
- project/ARK_AI_ACCEPTANCE.md
- core/scenario/ 下的运行配置

必须实现：
1. 世界完整一天等于现实 20 分钟（该旧 Goal 后续已更新）；每名 NPC 每天思考一次，思考时间错开，并依据人设、Goal、关系、当天事件和可见信息选择聊天对象。
2. NPC 先移动到目标附近，再显示邀请；被邀请者只输出接受或拒绝。拒绝时先保留请求气泡，再显示拒绝气泡。
3. 聊天最多三人。第三人可直接加入，原成员收到“谁加入了”的提示；第三名 NPC 不获得加入前记录。玩家必须主动加入或主动邀请，加入后可见此前聊天记录并自由输入。
4. NPC 收到新消息时可以同时决定发言、Goal 草稿变化、关系草稿变化、立场草稿变化，也只能通过 leave_chat 主动离开。Goal 完成或判断无法完成时可以离开世界。
5. 聊天中的草稿变化立即进入后续提示词；数据库权威更新仍遵循既有设计，但本阶段用内存提交替代。NPC 离开聊天或整场聊天结束时，生成个人化 Memory 节点，并提交 Goal、关系和章节立场变化。
6. Day1–Day7 公共事件按场景配置触发；当天事件直接进入提示词，后续作为内存 Memory 供检索。Day7 不调用模型和 Graph 临时猜测，而是使用已经提交的各 NPC 立场与议题态度执行固定结算规则。
7. 通过现有 TextModel 端口调用 Doubao-Seed-2.0-lite。为每类决策定义精简的 Pydantic 结构化输出。格式错误、超时、限流、缺少配置等常见失败要有明确、简单且可重试的处理，不能伪造角色决定。
8. REST/WebSocket 只能公开玩家可见信息；人设秘密、深层 Goal、私有 Memory、关系内部数值和模型提示词不得泄露。

实施原则：
- 第一版先保证完整逻辑和可玩性。
- 正常输入错误、配置缺失、状态冲突、网络超时、限流和模型格式错误必须兜底。
- 不为千分之一概率的理论风险增加熔断、多模型复核、分布式锁、多级缓存、复杂兼容层或大量未来抽象。
- 保持单体、内存、单一模型路径；本阶段不引入 PostgreSQL、Redis、Neo4j、消息队列或前端。
- 自动测试不得访问真实方舟网络；真实连通性测试只在用户轮换并本地设置新 ARK_API_KEY 后手动执行。
- 不覆盖用户已有修改，不写入或打印任何真实密钥。

协作方式：先由主会话写清本阶段设计与验收标准，再让 Luna Max 子智能体实现并自审，最后由主会话独立检查代码、运行 pytest/Ruff/mypy、修正问题并写入验收报告。完成后给出实际通过的测试结果、尚未实现的边界和下一步建议。
```
