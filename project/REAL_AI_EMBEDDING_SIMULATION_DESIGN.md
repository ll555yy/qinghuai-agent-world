# 真实 AI、Embedding 与七日模拟设计

状态：已确认，前端开发前置阶段。

## 1. 实施顺序

1. 验证方舟文本模型的六个协议：每日行动、邀请、聊天决策、台词、分段摘要、离场沉淀。
2. 接入真实 Embedding，并让新 Memory、历史回填与检索共用同一模型和维度。
3. 为 25 条有向初始关系补齐 NPC 私有 `scenario_seed` Memory。
4. 用真实方舟模型至少运行三次完整七日模拟：旁观、支持林慧兰/公益文化、支持赵磊/商业运营。
5. 根据报告调整 Prompt 和玩法参数；有证据才改，不凭单次台词直觉改。
6. 通过验收后再开发前端。

前端不是本阶段交付物。MCP、Redis、Neo4j、多场景和复杂生产级容灾也不在第一版范围内。

## 2. 文本模型验收

- 真实调用只能由显式 `--live` 命令触发；普通测试永不产生费用。
- 密钥只从本地环境读取，不进入源码、报告、日志或 Git。
- 六类协议分别记录：协议名、是否成功、结构化重试数、模型请求数、耗时、Token、提供方请求 ID 和安全错误码。
- 六类协议通过后，再用同一个 `RunService` 跑一个最小闭环，证明模型输出确实驱动 Agent 和世界状态，而非仅验证 SDK 连通。

## 3. Embedding 边界

- 文本生成继续使用 Agent Plan 地址；Embedding 使用方舟标准 `/api/v3/embeddings` 地址，二者独立配置。
- Embedding 模型必须显式配置。数据库向量维度、配置维度和模型实际返回维度必须完全一致；禁止截断、补零和伪向量。
- 第一版数据库统一采用 1024 维。变更模型或维度必须经过 Alembic migration，并全量重建向量。
- Memory 权威文本先提交数据库，网络调用在事务外进行；成功后定向更新该 Memory 的向量、模型和维度。
- 普通世界存档不能清空内容未变化的向量。Memory 内容改变时旧向量失效，等待重新生成。
- Embedding 失败时该 Memory 保持 `NULL`，检索回退到关键词、Actor/Goal/Topic 种子和 Graph 邻居；禁止写零向量。
- 回填工具必须显式执行、批量、幂等，可按模型和维度识别已完成记录，并报告成功、失败、跳过数量。
- 检索始终先按 `run_id + owner_npc_id` 隔离，再做向量、Graph、时间和重要度混合排序。

## 4. 初始关系 Memory

- 关系数值表是客观权威状态；Memory 保存 NPC 对目标角色的主观看法。
- 每条 `(fromActorId, toActorId)` 有向关系至少有一条 `scenario_seed` Memory：owner 是 `fromActorId`，`actorIds` 包含 `toActorId`。
- 20 条 NPC-NPC 关系使用由 Actor ID 派生的稳定 Memory ID；5 条 NPC-player 关系复用已有玩家印象 Memory，避免重复召回同义内容。
- 场景加载时检查 25 条边是否全部被覆盖，缺失时拒绝启动。

## 5. 七日模拟器

模拟器只驱动公开命令，不复制世界规则：

```text
ScenarioLoader → RunService → WorldEngine.step → Run/Event → MetricsCollector
```

三条必跑路线：

- `observer`：玩家不主动干预，用于观察 NPC 自运转是否成立。
- `pro_lin`：玩家优先支持林慧兰的公益文化方案。
- `pro_zhao`：玩家优先支持赵磊的商业运营方案。

每次固定并记录 seed。模拟器设置总模型请求、总消息、单场消息和墙钟时间硬上限；触顶时安全停止并将原因写入报告，不能无限烧额度。

报告同时输出 JSON 与 Markdown，至少包含：

- 最终世界时间、七个世界事件的触发/条件跳过情况；
- 每日 NPC 思考、移动、邀请、接受/拒绝、加入和等待；
- 对话数量、参与者、消息数、结束原因；
- Memory 生成/召回、Goal、关系和立场变化；
- Day7 分支、五项公开主张的核心/部分/未采纳结果、玩家任务结果；
- 六协议调用数、物理请求数、格式重试、提供方重试、失败码、延迟和 Token；
- 是否发生私有 Memory 越权或敏感字段进入公开快照。

## 6. 调参原则

三次真实模拟完成后再形成调参表。每项改动必须指向报告证据，例如：

- NPC 过于沉默：调整主动性阈值或 `wait` 提示，而不是强制每人发邀请。
- 对话过长：调整自动发言链和离场倾向，不改“一天 18:00 强制结束”。
- 立场不收敛：优化离场沉淀对立场证据的说明，不让模型直接写数据库结构。
- 召回不相关：调整混合检索权重或查询种子，不扩大 owner 可见范围。
- 格式错误多：缩短输出结构或按协议降低字段数量，不堆叠大量兜底。

第一版保留正常的超时、格式校验、调用上限和安全回退；不为极小概率情况引入复杂分布式架构。

## 7. 前端开工门槛

- 六协议真实调用有可复查报告；
- 真实 Embedding 写入、回填、持久化和语义检索通过；
- 25 条关系 Memory 加载校验通过；
- 三条七日路线均完成，或报告明确说明可复现的产品问题并已调整复跑；
- 全量离线测试、PostgreSQL 集成测试、迁移检查和敏感信息扫描通过；
- 项目文档与实际实现一致。
