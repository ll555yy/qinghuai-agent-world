# 可见体验参考研究

> 调研日期：2026-08-22
> 适用阶段：正式人物头像、慎之旧书店场景、聊天气泡与交互动效设计
> 使用原则：只提炼通用设计方法；除非许可证和来源已经核清，否则不复制代码、不下载素材、不临摹具体角色、地图或 UI 皮肤。

## 1. 当前项目基线

当前前端已经完成 React 19 + Phaser 3 + Zustand 的可玩闭环，但视觉仍属于功能原型：

- `BookstoreScene.ts` 用矩形和线条绘制书店，用带姓名首字的圆形表示人物；
- 场景气泡是单条 Phaser Text，1.5 秒后淡出，没有队列、避让和长文本降级；
- React 负责人物信息、聊天记录、请求卡、通知、日终遮罩和结局；
- Phaser 负责地图、人物位置、移动插值、聊天圈和短暂世界反馈；
- 时间变化主要体现在顶栏颜色与日终遮罩，场景本身没有明显的日照变化。

因此本轮调研不改变 React/Phaser 的既有职责，也不改变后端事件协议，目标是为下一阶段的原创视觉设计提供可执行依据。

## 3. 六个研究问题的设计结论

### 3.1 单场景俯视地图、景深与室内光照

参考 AI Town、Smallville、Kenney 模块化地图和 Tiny Bookshop 后，慎之旧书店不应做成“均匀铺满家具的平面图”，而应围绕聊天可读性建立三层空间：

1. **前景边框层**：靠近镜头的门框、垂落灯绳或半截书架，只作为轻量遮挡，透明度可降低，不能盖住人物头像和气泡；
2. **行动层**：中央长桌、柜台前、窗边、书架走道和健康角预留位，形成 4—5 个清晰停留点；NPC 的权威坐标映射到这些点，不改变后端坐标协议；
3. **背景叙事层**：高书架、修书台、旧窗、挂轴、漏雨位置等提供场景身份，但不做可交互物品，不暗示玩家拥有“操作任务”。

推荐构图：左侧高书架与修书台形成周慎之区域，中部留长桌作为三人聊天核心，右侧窗边和空角分别服务沈星遥与未来健康角，入口靠下，保证人物移动方向一眼可见。

光照不优先启用 Light2D。第一版采用两个低成本图层：

- 全天存在的暖色局部灯光渐变，绑定柜台/长桌附近；
- 按世界分钟插值的全场颜色覆盖层：白天近透明，17:00 后暖橙，17:50 后降低亮度，18:00 通过日终遮罩收束。

这样 Canvas/WebGL 都有一致降级效果，也不会要求每个美术资产制作 normal map。后续确认确有收益时，再试验 Phaser Light2D。

### 3.2 React 与 Phaser 的界面分工

现有边界应保留，并进一步固定：

| 表现 | 所属层 | 原因 |
|---|---|---|
| 地图、场景光、人物小头像、移动、聊天圈、头顶短气泡 | Phaser | 需要跟随世界坐标和摄像机缩放 |
| 完整聊天记录、自由输入、邀请/加入审批、人物公开信息 | React DOM | 中文排版、键盘焦点、滚动、可访问性和测试更可靠 |
| 当前时间、世界事件、日终、结局 | React 为主，Phaser 接收派生视觉阶段 | 权威信息必须稳定可读，场景只表达气氛 |
| 动效触发 | React/Zustand 消费服务器事件后投影给 Phaser | 避免 Phaser 自己推测业务状态 |

不新增第二套事件真相。Phaser 只接收公开快照和一次性视觉指令；动画被跳过或中断时，最终位置仍以服务器快照为准。

### 3.3 NPC 头像、状态标识与人物辨识度

人物不能只靠服装颜色区分。正式头像采用“面部轮廓 + 年龄特征 + 发型 + 主色 + 一个公开身份元素”的组合：

- 林慧兰：银灰短卷发、端正衣领、墨绿/米白，可出现普通书法笔但不能暗示秘密；
- 沈星遥：深色长发或低马尾、耳机、雾紫/蓝灰，姿态收拢；
- 赵磊：利落短发、衬衫或夹克、砖红/棕金，姿态外放；
- 陈月：清爽束发、社区护士的浅色衣装元素、青绿/白，不能使用真实医疗机构标志；
- 周慎之：沉静短发、深灰蓝/木色、简洁旧书店围裙或修书工具；
- 玩家：中性、低信息量的剪影式头像，不替玩家预设性别、职业或性格。

每名 NPC 第一版只需要三态：`neutral`、`speaking`、`tense`。状态变化以眉眼、嘴形和姿态小幅调整为主，不把隐藏关系或秘密画在脸上。场景小头像即使缩到 48—56px，也应保留主色环和姓名标签；当前说话者增加外圈脉冲，不频繁切换大幅表情。

### 3.4 多人聊天气泡的排队、归属和遮挡

场景气泡承担“远处也知道发生了什么”，完整文本仍由 React 聊天面板承担。采用以下规则：

- 每个 Actor 一个独立 FIFO 队列，同时只显示一个气泡；新消息不能销毁尚未读完的前一条；
- 气泡最多 2 行，建议 22—28 个中文字符，超出用省略号；完整内容永远保留在聊天面板；
- 停留时间按文本长度计算，建议 `1200ms + 字数 × 55ms`，限制在 1.8—4.2 秒；
- 气泡锚定人物头顶，屏幕边缘自动向内收；同一聊天圈出现重叠时按发言时间把后来的气泡上移一层，而不是横向覆盖人物；
- 系统状态如“邀请”“拒绝”“申请加入”使用短标签气泡，不和台词共用颜色；
- 三人聊天只显示当前台词和最多一个正在消退的上一条，不在地图上堆出三块长期文本。

视觉类型建议：台词为纸白底深墨字；邀请为槐叶绿描边；拒绝为低饱和朱砂；正在思考为三个点的非文字动效；加入/离开为中性系统标签。

### 3.5 邀请、拒绝、加入、离开与思考动效

动效只解释已经发生的服务器事件，不延迟或制造业务结果：

| 事件 | 建议动效 | 时长 |
|---|---|---|
| 开始靠近 | 人物面向目标并用 `Sine.easeInOut` 移动；脚下轻阴影随步幅变化 | 400—900ms，沿用现有距离策略 |
| 发出邀请 | 绿色描边请求气泡从 92% 放大到 100%，轻微上浮 | 180—240ms |
| 接受 | 双方主色环各闪一次，随后聊天圈淡入 | 220—320ms |
| 拒绝 | 朱砂短气泡 + 请求者极轻横向回弹一次，禁止连续抖动 | 260—360ms |
| 加入聊天 | 新成员向聊天圈中心靠近，圈线短暂扩张再回落 | 300—450ms |
| 离开聊天 | 聊天圈缩到剩余参与者范围，离开者状态标签淡出 | 240—360ms |
| 正在思考 | 头顶三个点依次变亮；收到后续状态事件立即停止 | 600ms 循环 |
| 离开世界 | 先显示公开离开标签，再把人物淡到 0；最终保留事件记录 | 500—700ms |

支持 `prefers-reduced-motion`：关闭位移回弹、缩放脉冲和循环呼吸，只保留 100—150ms 淡入淡出；权威坐标立即更新。

### 3.6 时间推进、黄昏与闭店

世界的一天是 20 分钟现实时间，但视觉不应每秒变化。把时间映射为四段：

| 世界时间 | 场景表现 | 交互信息 |
|---|---|---|
| 09:00—15:59 | 柔和日光、窗边偏亮、整体旧纸暖色 | 正常状态 |
| 16:00—16:59 | 光线略向金色移动，窗影拉长 | 不额外弹警告 |
| 17:00—17:49 | 暖橙覆盖层增强，店内灯更明显 | 顶栏明确“不可发起新聊天” |
| 17:50—17:59 | 环境轻微变暗，不闪烁；剩余时间持续可读 | 低打扰倒计时 |
| 18:00 | 场景冻结交互并淡入日终遮罩 | 后端强制结束聊天，进入日终 |

颜色插值只根据公开 `worldTime` 计算，不设置本地独立计时真相。重连后直接插值到当前时间段，避免从白天重新播放整段过渡。

## 4. 形成的原创美术方向

建议下一阶段先验证“温暖旧纸绘本感的 2D 俯视场景 + 半写实简化头像”，而不是直接套用通用像素包：

- **场景**：轻颗粒纸张质感、木色、墨绿和低饱和灯火橙；物件轮廓清楚但不做高频细节；
- **头像**：统一胸像裁切、柔和线条、保留成年人物的年龄和职业差异；不做幼态二次元模板脸；
- **UI**：纸张与旧书标签语言，圆角受控，避免现代 SaaS 卡片感过强；
- **动效**：安静、短促、以状态解释为目的，不用夸张弹跳；
- **信息层级**：地图看“谁与谁正在互动”，侧栏读“他们说了什么”，事件记录查“重要结果”。

下一步样稿应只制作：林慧兰、周慎之两名头像；一张书店整体构图；普通台词与拒绝两类气泡；一张 React + Phaser 合成界面。确认风格后再批量制作其他人物与状态。

## 5. 明确不采用的方案

- 不把 Coffee Talk 的横向角色立绘、对话框比例或配色直接复刻；
- 不导入 Smallville、AI Town 或 Phaser Examples 中授权未逐项确认的美术；
- 不用通用 CC0 像素包拼出最终书店后再搭配另一种画风的头像；
- 不让三个 NPC 的完整长台词长期堆在场景中；
- 不为了灯光效果把运行模式锁死为 WebGL；
- 不加入复杂骨骼动画、自由移动、地图编辑器或新的玩法状态；
- 不根据 NPC 私密 Goal、关系数值或秘密生成玩家可见表情和图标。

## 7. 调研结论

本项目最适合保留现有“React 稳定承载长文本与操作，Phaser 表达空间和短反馈”的架构。视觉升级的核心不是增加更多系统，而是让玩家在两秒内看懂人物身份、聊天组合、当前动作和时间阶段。所有参考项目只提供方法论；正式角色、地图和 UI 应形成青槐老巷自己的原创视觉语言。
