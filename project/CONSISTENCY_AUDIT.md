## 已修正的问题

| 问题 | 风险 | 统一后的规则 |
|---|---|---|
| `ChatDecision.result` 同时出现 `retrieve_memory/decision` 与 `need_memory/decided` | Schema 和分支处理无法统一 | 只使用 `need_memory | decided` |
| `ExitConsolidation` 再次输出 Goal、关系变化，可能被当作第二次增量应用 | 同一变化重复计算 | 聊天决策只更新会话草稿；离场输出用于生成可追溯 Memory，正式状态只按草稿提交一次 |
| 单个 `chapterEffect` 无法同时表达总体立场和多项公开主张态度 | 一场聊天中多个明确表态会丢失 | 改为 `chapterEffects` 数组，每项独立带证据 |
| 玩家消息触发模型等待时以“必须返回台词”为结束条件 | 全部 NPC 选择等待时会永久停表 | 以前台决策周期完成为结束条件，台词是可选结果 |
| 所有人等待后 Conversation 没有可靠结束条件 | 聊天长期占用角色和两个会话名额 | 增加 `conversation_idle` 收束；仍无人说话则结束会话并沉淀 |
| “observed”事件按同一场景或聊天参与者判断 | 五名 NPC 都在单场景中，会导致私有事件错误地全员知晓 | 按事件区域、角色坐标和可见半径计算亲历者，与聊天成员身份无关 |
| Day5 世界事件固定写出周慎之的反应 | 与 NPC 反应必须动态决定冲突 | 事件只固定旧函套受潮，周慎之如何反应由模型决定 |
| 早期规则仍写邀请可“推迟” | 与 `accept/refuse` 冲突 | 删除推迟，仅保留接受或拒绝 |
| D-046 写 NPC 不能离开世界 | 与后续 D-057 冲突 | D-057 覆盖 D-046：离场沉淀后没有 `active | blocked` Goal 的 NPC 进入 `departed` |
| 玩家核心行为清单遗漏主动邀请、查看资料和任务选择 | UI 与权限实现可能漏功能 | 已补齐当前完整玩家行为集合 |
| 旧“讨论中”草案包含已被覆盖的待确认项及“摘要带 owner”文字 | 容易被误当成当前规则，且与共享片段摘要冲突 | 删除过期草案，改为实施待办清单 |
| “一天十分钟”与 Day1 09:00、Day7 18:00 的显示时间缺少换算 | 事件调度会出现不同实现 | 每日活跃窗口 08:00～18:00，每现实有效分钟推进一虚拟小时；Day1 从 09:00 开始，约 69 分钟，界面仍标约 70 分钟 |

## 看似矛盾但属于有意设计

- 玩家加入聊天后可以查看加入前记录，后来加入的 NPC 不可以。这是玩家阅读能力与 NPC 信息边界的刻意不对称。
- Goal 和关系在聊天中立即影响行为，但正式数据库等 NPC 离场时才提交。会话草稿是当前有效状态，不是第二套世界真相。
- Graph 用于 NPC 长期语义召回；章节总体立场和公开主张态度使用结构化状态表结算，不依赖 Graph 检索。
- 世界可以同时有两场聊天，但每名角色只能属于一场；信息和会话草稿按 `conversationId` 完全隔离。
- 未 `departed` 的 NPC 属于当前世界；观察型事件仍可能只有少数角色看见，因为可见性由事件配置/观察者集合而不是世界成员资格决定。
