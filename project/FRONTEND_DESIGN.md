# 第一版前端设计

> 状态：已确认玩法约束下的实施设计
> 更新时间：2026-08-21
> 目标：用 React + Phaser 完成从前情提要到 Day7 结算的可玩浏览器客户端。

## 1. 设计结论

第一版采用“React 应用壳 + Phaser 单场景”的桌面优先布局。FastAPI Run 是唯一权威状态；前端只缓存公开快照、按事件播放表现，并发送玩家命令。NPC 的 Goal、关系数值、Memory、秘密、模型推理和草稿均不进入前端契约。

完整流程：

```text
前情提要 → 选择支持主张 → 创建 Run → 七日世界主界面
                                  ↓
                    观察 / 邀请 NPC / 申请加入聊天
                                  ↓
                         自由输入并影响 NPC
                                  ↓
                      日终过渡 → 下一日世界事件
                                  ↓
                  Day7 18:00 → 主张采纳与玩家任务结算
```

后端现有能力足以支撑主流程。唯一明确缺口是没有独立的玩家自由移动命令。为保持后端权威，第一版不实现任意走动：邀请时使用后端 `actor_movement_*` 事件播放靠近；申请加入时由界面播放“走向聊天圈”的短过渡后提交请求，但不把本地坐标写成权威状态。真正自由走动延后到后端提供移动命令后再做。

## 2. 页面与阶段

### 2.1 前情提要

- 标题：`七日方案期`。
- 说明旧书店将在 30 天后被收回，七天内可以提交承接方案。
- 告知玩家所有问题都通过观察和聊天解决，没有物品、搬运或点击完成任务。
- “查看可选立场”进入任务选择。

### 2.2 玩家任务选择

- 从后端 `agendas` 渲染五张公开主张卡。
- 每张卡只显示提出人、标题和公开概要。
- 允许“不选择立场，作为旁观者进入”。创建 Run 时 `agendaId=null`。
- 选定后创建 Run；选择只定义结局中的玩家任务，不限制玩家说什么。

### 2.3 世界主界面

桌面端文字线框图：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Day 2 / 7  10:24  [17:00后不可发起新聊天]      当前任务  [事件记录] │
├─────────────────────────────────────────────┬────────────────────────┤
│                                             │ NPC公开信息 / 聊天面板 │
│          Phaser：慎之旧书店单场景           │                        │
│                                             │  林慧兰  周慎之         │
│   书架     NPC头像 ○○      聊天圈 ◌         │  ───────────────       │
│                 玩家头像                    │  消息记录               │
│                                             │  ……                    │
│   移动、邀请、拒绝、等待、气泡均在场景表现   │  [输入内容……] [发送]   │
│                                             │  [离开聊天]             │
├─────────────────────────────────────────────┴────────────────────────┤
│ 状态提示：世界已连接 / 正在等待 NPC / 某人拒绝了邀请                 │
└──────────────────────────────────────────────────────────────────────┘
```

- 宽度大于 1100px 时右侧面板固定为 360px。
- 较窄窗口中右侧面板作为覆盖抽屉，场景仍保留至少 640px 可视宽度。
- 顶栏显示 Day、世界时间、当前任务、连接状态和事件记录入口。
- 场景内气泡短暂显示；关键结果同步进入底部通知，不依赖一闪而过的动画。

### 2.4 NPC 右键菜单与公开信息

右键 NPC 显示：

- `了解信息`：调用公开 Actor 接口，显示姓名、身份、公开背景、公共印象和当前可见状态。
- `发出聊天邀请`：仅在 NPC 未离场、未聊天、时间早于 17:00 且玩家未在聊天时可用。

按钮禁用只是体验提示，后端仍执行最终校验。前端绝不展示 personaSummary、traits、values、boundaries、coreSecrets、Goal、关系或 Memory。

### 2.5 邀请与加入聊天

- 玩家邀请 NPC：显示玩家靠近动画和“发出邀请”气泡；后端返回后显示接受或拒绝。
- NPC 邀请玩家：显示请求卡，只有“接受”和“拒绝”。
- NPC 邀请 NPC：前端只播放气泡与结果，不提供玩家按钮。
- 玩家点击未满三人的聊天圈后选择“申请加入”。加入必须由后端获得所有当前 NPC 参与者同意。
- NPC 申请加入包含玩家的聊天时，玩家收到接受/拒绝卡；没有玩家参与时由 NPC 自主决定。
- 17:00 后不再创建新邀请或加入请求；已有聊天可继续到 18:00。

### 2.6 聊天面板

- 成功加入后自动打开，显示当前参与者、世界时间和完整可读历史。
- 玩家可以自由输入 1—2000 字；发送期间仅锁定发送按钮，不冻结世界 UI。
- `message_created` 追加公开文本；`conversation_activity` 只显示“对话仍在继续/暂时无人发言”等非文本状态，不能伪造 NPC 台词。
- `conversation_participant_joined/left` 生成居中的系统消息。
- 玩家离开后仍可查看自己曾参与过的历史，但不能继续发言。
- 聊天关闭时显示后端 `closeReason` 的中文说明；日终、少于两人、连续无发言和章节截止均有不同文案。

### 2.7 世界事件与日终

- `world_event_occurred` 以顶部横幅展示公开或玩家亲历事件，并写入事件记录。
- 事件记录只使用公开快照中的事件，前端不能从 YAML 推断玩家本不知情的 observed 事件。
- 17:00 顶栏切换为暖橙色并提示“不可发起新聊天”。
- 17:50 起显示低打扰倒计时。
- `world_day_ended` 后展示日终遮罩；`world_day_started` 到达后关闭遮罩并展示新 Day。
- 世界时间由前端每 2 个有效前台现实秒调用一次 `world/step`；页面隐藏、请求未完成、章节结束或连接丢失时不累计补时，防止重连后一口气跨日。

### 2.8 NPC 离开

公开状态为 `departed` 时，头像淡出并在事件区显示“已离开当前世界活动”。前端不推测离开原因；只有后端公开事件或聊天内容明确说明时才显示原因。

### 2.9 Day7 结局

结局数据以 `chapterResolution` 为准：

- `branch`：一致提交、妥协提交或未提交。
- `agendaResults`：逐项展示核心采纳、部分采纳或未采纳。
- 每项主张的提出人从公开 Agenda 映射。
- `playerTaskResult`：完成、部分完成、失败，旁观路线不显示任务成败。
- `actorStances`：展示五名 NPC 在截止时已经公开形成的支持、附条件、反对、退出或未表态状态。
- `playerHighlights`：展示最多五条玩家实际发言，作为可验证的参与记录；前端不把相邻关系伪装为严格因果归因。

上述字段由后端在 Day7 结算事务内生成公开投影。前端只消费结算结果，不读取数据库中的私有立场草稿、Goal、关系或 Memory。

## 3. React、Phaser 与状态边界

### React

- 应用阶段、提要、任务选择、顶栏、信息抽屉、聊天、通知、日终和结局。
- 发起 REST 命令，维护 WebSocket 生命周期。
- 从公开快照派生按钮可用性和显示文案。

### Phaser

- 书店背景、Actor 头像、名字、状态标记、移动插值、聊天圈和短气泡。
- 接收 Zustand 公开投影；不直接访问 REST、WebSocket 或保存 Run。
- 右键命中后只上报 actorId 给 React。

### Zustand Store

| Slice | 内容 | 来源 |
|---|---|---|
| `run` | runId、版本、世界时间、公开事件、结局 | 服务器快照/事件 |
| `actors` | 公开资料、公开状态、权威坐标 | 服务器快照/事件 |
| `conversations` | 会话、参与者、公开消息 | 服务器快照/REST/事件 |
| `requests` | 玩家可响应的邀请和加入请求 | 服务器事件 |
| `connection` | ws 状态、afterSeq、重连次数、最近错误 | 本地通信状态 |
| `ui` | 当前抽屉、菜单坐标、选中 Actor、toast | 纯本地 |

事件只在 `eventSeq` 大于已处理序号时应用；版本或事件出现缺口时重新 GET Run 和可读消息，不猜测中间状态。

## 4. 视觉规范

- 背景：旧纸 `#F3EBD8`、浅木 `#C79A68`、深木 `#684832`、墨色 `#29251F`。
- 强调：槐叶绿 `#667A5A`；警告：灯火橙 `#C8793B`；错误：朱砂 `#A64B3C`。
- 正文字体使用系统中文无衬线；标题使用系统衬线栈，避免额外字体下载。
- NPC 头像第一版为带姓名首字的圆形占位头像，不引入秘密暗示。
- 动效 120—320ms；移动动画按事件距离控制在 400—900ms，不能阻塞状态更新。

## 5. 常见故障处理

- 首屏健康检查失败：保留提要页并提供“重新连接”。
- REST 业务错误：显示后端 `error.message` 的中文映射，保留重试入口。
- WebSocket 断开：指数间隔只做 1s/2s/5s 三档，重连携带 `afterSeq`；连续失败后允许手动重连。
- 消息发送失败：保留输入文本，不插入乐观假消息。
- 世界步进失败：停止计时器，重新同步快照后恢复。

## 6. 第一版明确延后

- 玩家任意自由走动和路径碰撞（需要后端移动命令）。
- 对玩家发言进行严格因果归因（第一版只展示可验证发言与最终公开结果）。
- 多地图、地图编辑器、复杂动画、背包和操作任务。
- 移动端深度适配、桌面壳和多人联网。

上述延后项不阻塞现有“观察—邀请—加入—聊天—七日结算”闭环。
